⚠️ Critical Architecture Notice: While the user interface covers the complete purchase funnel, there are several backend database disconnects (notably Return Requests and Payment Processing) where data remains trapped in local React state or localStorage instead of entering the server database.

🔴 2. Critical Backend & Data Integration Gaps (Must Fix First)

These are high-priority structural issues where frontend actions fail to persist in the PostgreSQL database:

Gap / Issue Severity Current Technical Flaw Required Action
Return Request Database Disconnect Critical ReturnRequest.jsx updates order status to RETURN_REQUESTED and saves data to browser localStorage, but does NOT insert a row into the Prisma ReturnRequest table. Create POST /api/v1/returns endpoint in backend and link handleSubmitReturn() so Admin Panel's /admin-returns sees customer defect photos, reason & UPI.
Hardcoded Localhost URLs Critical In ReturnRequest.jsx (lines 233 & 270), http://localhost:5000/api/v1 is hardcoded instead of using Vite's import.meta.env.VITE_BACKEND_URL. Replace with dynamic environment variable; otherwise network requests fail on production, tunnels, or LAN testing.
Payment Gateway Integration Critical In checkout_payment.jsx, UPI, Debit Card, and NetBanking payments are simulated with mock timeouts. No real payment transaction happens. Integrate Razorpay or Cashfree SDK with server-side order generation and webhook signature verification (COD is currently fully operational).
Review Helpful Votes Not Persisted Medium On the reviews page, clicking "Helpful" upvotes is stored only in React component memory. Refreshing the browser resets the vote count. Add a POST /api/v1/reviews/:id/vote route to store user upvotes in the database.

🟡 3. Missing Core Meesho Customer Features

Standard e-commerce features present on Meesho India that are currently absent from the customer panel:

Feature Name Impact Description & Missing Logic Target Screen
Pincode Delivery Estimator High Missing an "Enter Pincode to check delivery date & COD availability" widget on the PDP. Customers cannot check transit duration or eligibility prior to checkout. product_detail.jsx
Phone Number + OTP Login High Meesho's primary sign-in mechanism is SMS/WhatsApp OTP. Current system only provides Email/Password and Google OAuth. UserLogin.jsx
Supplier Storefront View Medium Clicking "Sold by: [Supplier Name]" on the product page does not open a dedicated seller profile page with all products from that merchant. product_detail.jsx ➔ /store/:id
Similar / Recommended Products Medium The bottom of the Product Detail page lacks a dynamic recommendation algorithm (matching categorySlug or shared tags from the database). product_detail.jsx
Customer Notifications Feed Medium The existing /notifications center is configured for resellers (margin credits, withdrawals). Missing customer alerts (Dispatched, Out for Delivery, Wishlist Price Drops). NotificationCenter.jsx
Live Delivery GPS Map for Customer Low Driver app has live route GPS maps, but customer's order tracking modal only displays linear text milestones without rider position display. CustomerOrders.jsx
Order Support / Ticket Redirection Low No one-click "Need Help with this Order" button on orders that passes the orderId directly to the support center ticket modal. CustomerOrders.jsx ➔ /support-center

🚀 5. Recommended Priority Implementation Roadmap

Structured 4-phase rollout to achieve 100% production readiness for the Customer Panel:

PHASE 1 • PRIORITY 1 Immediate
Fix Return Request Backend & Admin Sync
Build POST /api/v1/returns endpoint in backend. Insert into Prisma ReturnRequest table so Admin Panel displays uploaded defect photos, reasons, and UPI details. Fix localhost URLs.
PHASE 2 • PRIORITY 2 High
Pincode Estimator & Seller Store
Implement Pincode lookup on Product Detail Page with standard delivery date calculation. Add customer-facing Seller Storefront page (/store/:supplierName).
PHASE 3 • PRIORITY 3 Medium
Dynamic Flash Sale & Bottom Nav Fix
Connect /flash to real discounted database products. Pass role="customer" across all customer pages so bottom dock shows correct tabs (Wishlist instead of Earnings).
PHASE 4 • PRIORITY 4 Finishing
Payment Gateway SDK & OTP Login
Integrate live Razorpay/Cashfree checkout modal with server signature validation. Add optional Firebase Phone OTP authentication widget for mobile-first users.
